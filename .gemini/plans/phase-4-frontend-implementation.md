# Feature: Phase 4: Frontend Implementation

The following plan should be complete, but its important that you validate documentation and codebase patterns and task sanity before you start implementing.

## Feature Description

This phase focuses on building the user-facing web application for the AI Interviewer. It transforms the backend-only system into a fully interactive experience where candidates can upload resumes, participate in a real-time voice interview with an audio visualizer, and view their final hiring report.

## User Story

As a candidate
I want to upload my resume and connect to a voice session seamlessly
So that I can experience a modern, professional AI-led interview.

As a candidate
I want to see visual feedback when I or the AI is speaking
So that I know the system is active and responsive.

## Problem Statement

The backend infrastructure for resume parsing and real-time voice interaction is complete (Phases 1-3), but there is currently no way for a user to interact with the system without using CLI tools or manual API calls. A professional web interface is required to orchestrate the multi-step interview flow.

## Solution Statement

Implement a React (Vite) single-page application (SPA) using Tailwind CSS and Shadcn UI. The frontend will integrate the LiveKit React SDK for real-time WebRTC communication. It will guide the user through a four-stage workflow:
1. **Upload**: Resume PDF upload and plan preview.
2. **Setup**: Microphone permissions and connection logic.
3. **Interview**: Real-time voice interaction with an "Aura" visualizer and live transcript.
4. **Results**: Presentation of the structured hiring report.

## IMPLEMENTATION PLAN

### Phase 1: Foundation (Scaffolding)

Set up the React project, configure styling, and install core dependencies including the specialized LiveKit Agents UI.

**Tasks:**
- Scaffold Vite + React (TypeScript).
- Install Tailwind CSS and Shadcn UI.
- Install `@livekit/components-react`, `livekit-client`, and `@livekit/agents-ui-react`.
- Configure CORS in the FastAPI backend to allow the frontend to connect.

### Phase 2: API & State Management

Build the bridge between the frontend and the existing FastAPI backend.

**Tasks:**
- Create `api/client.ts` with methods for `uploadResume`, `getToken`, and `getReport`.
- Implement a `useInterview` hook to manage the workflow state (UPLOAD -> PREVIEW -> CALL -> REPORT).
- Update `backend/api/main.py` to store and serve the `FinalReport` generated by the worker.

### Phase 3: Core UI Components (Agents UI)

Implement the individual screens using high-quality LiveKit specialized components.

**Tasks:**
- **UploadScreen**: File dropzone with PDF validation using Shadcn.
- **InterviewAgent**: A specialized container wrapped in `AgentSessionProvider`.
- **AudioVisualizer**: Utilize `AgentAudioVisualizerAura` for high-fidelity feedback.
- **TranscriptView**: Utilize `AgentChatTranscript` for real-time conversation history.
- **ControlBar**: Utilize `AgentControlBar` for mic and connection management.
- **ReportView**: Beautiful display of the hiring decision, scores, and summary.

### Phase 4: Integration & Workflow

Connect the components and orchestrate the full end-to-end flow.

**Tasks:**
- Handle token retrieval and room joining.
- Implement "End Interview" logic that triggers report generation and transition to the result screen.
- Add "Setup" screen for microphone testing using LiveKit pre-join components.

### Phase 5: Testing & Validation

**Tasks:**
- Verify WebRTC connectivity with the LiveKit worker.
- Test the full flow: PDF Upload -> Voice Call -> Report Display.
- Ensure responsive design and accessibility.

## TESTING STRATEGY

### Manual Validation Flow
1. **Upload**: Drag `test_resume.pdf` into the browser.
2. **Preview**: Verify candidate name and skills are displayed.
3. **Connect**: Click "Start Interview", allow microphone.
4. **Interact**: Speak to the AI, verify the visualizer pulses.
5. **Complete**: Say "I'm finished", wait for the report screen.
6. **Verify**: Check that the JSON report is rendered clearly.

### Edge Cases
- **Mic Access Denied**: UI should show a clear error message.
- **Backend Offline**: API calls should fail gracefully with a toast notification.
- **Large PDF**: Test upload progress and handling of parsing timeouts.
